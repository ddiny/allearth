> 새 기능을 추가할 때 기존 AllEarth의 브랜드, 시각적 위계, 컴포넌트 사용 방식을 유지하기 위한 작업 기준.
>
> 문서 버전: 1.5 · 작성일 및 Figma 확인일: 2026-10-20
>
> Figma 읽기 조사 결과와 별도로 표시한 확장 규칙을 정리한 문서다. Figma 원본은 수정하지 않았으며, 18장의 접근성 규칙과 19장의 가입 화면 규칙은 HTML 프로토타입에 적용했다.

### 1.2 근거 구분

이 문서에서는 다음 표기를 사용한다.

- **[확인]**: Figma의 설명, 텍스트, 속성, 컴포넌트 구조 또는 화면에서 직접 확인한 사실.
- **[채택]**: 원본의 불일치를 그대로 복제하지 않도록, 이 가이드가 새 기능에 적용하기로 정한 기준. 원본이 이미 수정됐다는 의미는 아니다.
- **[확장]**: 원본에 없는 상황을 기존 디자인에 맞게 처리하기 위한 운영·구현 규칙. 원본의 공식 규정으로 주장하지 않는다.
- **[미확인]**: 조사 범위에서 수치나 동작을 확인하지 못한 항목. 임의로 확정값처럼 사용하지 않는다.

각 절의 기본 근거를 제목이나 첫 문장에 명시한다. 한 절 안에서 근거가 달라지는 항목은 별도 표기한다.

### 1.3 새 기능을 위한 우선순위

**[확장]** 아래 순서로 디자인을 결정한다.

1. 같은 역할의 기존 컴포넌트와 해당 컴포넌트의 언어·상태 변형을 찾는다.
2. 이 문서의 브랜드·타이포·색상 기준과 일치하는 컴포넌트를 재사용한다.
3. 원본 문서와 실제 컴포넌트가 다르면 12장의 결정표를 적용한다.
4. 기존 구성으로 해결되지 않는 부분만 새 변형 또는 새 컴포넌트로 만든다.
5. 새로운 의미·상태·토큰을 추가했다면 근거와 적용 범위를 이 문서에 기록한다.

기존 오류를 새 기능에 복제하지 않는다. 반대로 새 기능 하나를 위해 기존 화면 전체의 디자인을 일괄 변경하지도 않는다. 기존 화면의 수정이 필요하면 영향 범위를 별도 변경으로 기록한다.

## 2. 빠른 적용 규칙

**[확인 + 채택 + 확장 요약]** 세부 근거는 각 장과 12장에 있다.

1. 한글은 **Pretendard**, 영문은 **Poppins**를 기본으로 사용한다.
2. 색상은 의미별 토큰으로 사용한다. 임의의 비슷한 회색이나 라임을 추가하지 않는다.
3. 기본 색상은 **Lime `#DEFA5F` / Ink `#23262C` / Paper `#FFFEFB`**다.
4. Lime은 로고·중요 강조·선택 상태에 사용하고, 화면에서 차지하는 면적을 10~20% 이하로 관리한다.
5. 한 화면의 **Primary 버튼과 Lime 버튼 합계는 1개**로 한다. 나머지 액션은 Secondary 또는 Text로 낮춘다.
6. 버튼 라벨은 Bold 14px, 한 줄을 기본으로 한다. 일반 버튼 반경은 999px다.
7. 같은 기능은 KR/EN에서 같은 의미, 상태, 데이터 구조를 유지한다. 번역 때문에 생기는 높이 차이는 허용한다.
8. 아이콘의 선택 여부는 색상만이 아니라 Outline/Solid 변화로 표현한다.
9. 모바일 샘플의 고정 너비를 모든 화면에 강제하지 않는다. 컨테이너 너비와 텍스트 길이에 대응한다.
10. 새 기능은 정상 화면뿐 아니라 필요한 입력·로딩·빈 결과·실패 상태까지 같은 디자인 언어로 정의한다.

## 3. 브랜드와 로고

### 3.1 로고 구성 [확인]

- Primary Logo는 심볼과 워드마크가 고정된 관계로 결합된 형태다.
- 브랜드 가이드에는 심볼 단독, 기본형, 전체 이름 가로형, 전체 이름 세로형이 있다.
- UI 컴포넌트에는 `Logo`의 `type=Vertical/Horizontal` 변형이 있다.
- Vertical UI 샘플은 약 114×84이며 `allearth` 워드마크를 사용한다.
- Horizontal UI 샘플은 약 114×40.67이며 짧은 로고 조합을 사용한다.

### 3.2 심볼 규칙 [확인]

| 항목 | 규칙 |
| --- | --- |
| 모티프 | 지구의 경선·위선을 암시하는 원과 두 줄의 컷 |
| 컷 각도 | 지구 자전축의 기울기에서 가져온 **23.4°** |
| 컷 두께 | 심볼 지름의 **7.5%** |
| 교차점 | 원 중심에서 좌하단으로 약간 이동 |
| 교차점의 정확한 이동값 | **[미확인]** 숫자 명세 없음 |

### 3.3 새 기능에서의 사용 [확장]

- 기존 로고 자산이나 Figma 컴포넌트를 사용한다. 텍스트와 임의의 원·선으로 로고를 다시 그리지 않는다.
- 비율, 컷 각도, 심볼·워드마크의 상대 배치를 유지한다.
- 좁은 공간에서는 제공된 심볼 단독 또는 짧은 조합을 선택한다.
- 로고 최소 크기·보호 여백·역상 로고의 전체 사용표는 이번 조사에서 확정되지 않았다. 필요 시 원본 자산을 추가 확인하고 결정값을 기록한다.

## 4. 색상 토큰

### 4.1 새 기능의 기준 팔레트 [채택]

Lime과 Paper는 **Brand Guidelines의 표기·색상 면과 UI 컴포넌트의 실제 연결 변수**가 일치하는 값을 채택한다. Earth 색상은 브랜드 가이드의 확인값을 채택하되, 실제 지구본 구현의 변수 연결은 확인하지 않았다.

| 의미 토큰 | HEX | 용도 | 확인 근거 |
| --- | --- | --- | --- |
| `color/lime` | `#DEFA5F` | 로고, 주요 강조, 선택 상태, Lime 액션 | 브랜드 + 실제 외부 변수 |
| `color/ink` | `#23262C` | 주요 텍스트, Primary CTA, 선택된 GNB 배경 | 브랜드 + 실제 외부 변수 |
| `color/paper` | `#FFFEFB` | 바탕 면, 태그·세그먼트 등 부드러운 면 | 브랜드 + 실제 외부 변수 |
| `color/mute` | `#5C5F66` | 보조 설명, 시각·메타 정보 | 브랜드 + 실제 외부 변수 |
| `color/gray` | `#CECECE` | 지도 블록, 비활성 표현, 일부 placeholder | 브랜드 + 실제 외부 변수 |
| `color/line` | `#E6E5DF` | 구분선, 외곽선, 일부 Disabled 배경 | 브랜드 + 실제 외부 변수 |
| `color/white` | `#FFFFFF` | 흰 컴포넌트 면, Ink 위 텍스트 | 상단 캡처 + 실제 외부 변수 |
| `color/earth-ocean` | `#B2D0DD` | 지구본 바다 | 브랜드 가이드 |
| `color/earth-land` | `#CCE2AA` | 지구본 육지 | 브랜드 가이드 |

`Graphite`는 일부 설명·레이어에서 Ink에 대응하는 명칭으로 쓰인다. 새 토큰 이름은 `ink`로 통일한다.

### 4.2 적용 규칙

**[확인]**

- 보조 텍스트는 Mute, 구분은 Line, 지구본은 Earth 계열을 사용한다.
- Lime은 화면의 10~20%를 넘기지 않도록 한다.
- 밝은 바탕의 상태 아이콘에는 Lime을 사용하지 않는다. 선택 아이콘의 Lime은 어두운 면 위에서 사용한다.
- 브랜드 설명은 불투명도를 스크림·글래스 바·그림자에 한정한다.

**[채택]**

- 버튼 가이드에 별도로 적힌 Pressed 불투명도는 상호작용 상태의 예외로 다룬다. 적용 방식은 7장과 12장에 명시한다.
- White와 Paper를 같은 값으로 합치지 않는다. 컴포넌트가 사용하는 면의 의미를 유지한다.

**[확장]**

- 오류·성공·경고 의미의 전용 색상은 이번 팔레트에 정의돼 있지 않다. 임의의 빨강·초록을 화면마다 추가하지 않는다.
- 우선 명시적인 문구와 아이콘으로 상태를 전달한다. 전용 상태색이 필요하면 의미 토큰을 새로 정의하고 대비·관련 화면을 함께 검토한다.
- 이 팔레트가 모든 배경·크기에서 접근성 기준을 통과했다는 의미는 아니다. 실제 조합에서 가독성을 확인한다.

### 4.3 상단 캡처의 다른 값 [확인]

| 항목 | 상단 Color 캡처 | 이 문서의 채택값 |
| --- | --- | --- |
| Lime | `#D8F55A` | `#DEFA5F` |
| Paper | `#F8F7F2` | `#FFFEFB` |
| Earth Ocean | `#A8CCDB` | `#B2D0DD` |
| Earth Land | `#C6DBA6` | `#CCE2AA` |

캡처가 만들어진 날짜나 변경 이력은 확인하지 않았다. 따라서 어느 자료가 시간상 최신인지 단정하지 않는다. 새 작업에서는 위의 채택값을 사용한다.

## 5. Typography

### 5.1 언어별 역할과 수치 [확인]

크기는 px, 자간·행간은 글자 크기 대비 비율이다.

| 역할 | 크기 | KR: Pretendard 굵기 | KR 자간 | KR 행간 | EN: Poppins 굵기 | EN 자간 | EN 행간 |
| --- | ---: | --- | ---: | ---: | --- | ---: | ---: |
| Display | 40 | Black 900 | -2% | 120% | Bold 700 | -4% | 110% |
| Heading | 28 | ExtraBold 800 | -2% | 120% | Bold 700 | -2% | 110% |
| Title | 20 | ExtraBold 800 | -2% | 120% | Bold 700 | -2% | 110% |
| Body | 14 | Regular 400 | -2% | 130% | Regular 400 | 0% | 130% |
| Label | 12 | Bold 700 | 0% | 120% | Bold 700 · Uppercase | -2% | 110% |
| Caption | 12 | Regular 400 | 0% | 130% | Regular 400 | 0% | 130% |
| Button | 14 | Bold 700 | -2% | 130% | Bold 700 | -2% | 110% |

- Caption은 날짜·보조 문구, Button은 버튼·칩에 사용한다.
- 가이드의 샘플 텍스트 속성과 위 수치는 일치했다.
- EN Label의 가이드에는 Uppercase가 적혀 있지만 예시 `hot`, `TAiwan`은 대소문자가 혼재한다.
- **[채택]** 새 EN Label은 Uppercase로 표시한다. Body·버튼·제목 전체에 이 규칙을 확장하지 않는다.

### 5.2 실제 스타일 연결 [확인]

중간 컴포넌트에는 외부 라이브러리의 다음 11개 Text Style이 실제 연결돼 있다.

- KR: Heading, Title, Body, Label, Caption, Button.
- EN: Heading, Title, Body, Caption, Button.

Display와 EN Label이 이 컴포넌트 영역의 연결 목록에 없다는 사실은 브랜드 스타일 정의가 없다는 뜻이 아니다. 또한 일부 텍스트는 직접 속성을 갖고 있어 모든 텍스트가 스타일에 연결된 상태는 아니다.

**로컬 스타일 목록에 없다는 이유로 미등록·미사용이라고 판단하지 않는다.** 연결된 `textStyleId`의 원본 스타일과 `remote` 여부를 확인해야 한다.

### 5.3 새 화면 적용 [확장]

- 글자 크기를 화면마다 임의로 정하기 전에 Display/Heading/Title/Body 등의 역할을 먼저 선택한다.
- KR/EN 전환 시 번역뿐 아니라 폰트, 굵기, 자간, 행간도 함께 전환한다.
- 영문 길이가 길어지면 허용된 줄바꿈과 컨테이너 높이 증가로 대응한다. 폰트를 임의 축소해 맞추지 않는다.
- 버튼의 한 줄 원칙과 긴 본문의 줄바꿈 정책을 구분한다.
- 숫자·시간·지역명·번역된 메타 정보도 언어별 스타일을 확인한다.
- 로고 워드마크처럼 별도 디자인된 자산을 일반 Typography 규칙으로 재생성하지 않는다.

### 5.4 구현 시 단위 변환 [확장]

```css
/* 단위 변환 예시. 실제 프로젝트의 토큰·컴포넌트 구조에 통합한다. */
.body-kr {
  font-family: "Pretendard", sans-serif;
  font-size: 14px;
  font-weight: 400;
  letter-spacing: -0.02em;
  line-height: 1.3;
}

.button-en {
  font-family: "Poppins", "Pretendard", sans-serif;
  font-size: 14px;
  font-weight: 700;
  letter-spacing: -0.02em;
  line-height: 1.1;
}
```

`-2%`를 `-2px`로 옮기지 않는다. 위 코드는 폰트 파일을 설치·로드하지 않는다. 폰트 로딩과 제공 굵기는 구현 환경에서 별도로 확인한다.

## 6. 형태, 간격, 면과 반응형

### 6.1 Radius [확인]

| 토큰 | 값 | 근거 및 범위 |
| --- | ---: | --- |
| `radius/full` | 999 | 캡처 + 실제 연결 변수. 일반 버튼·Pill |
| `radius/sheet` | 12 | 상단 캡처. 실제 전체 시트 구현은 미검토 |
| `radius/card` | 8 | 상단 캡처. 카드 내부 면·이미지 등의 개별 적용 확인 필요 |
| `radius/field` | 8 | 캡처 + 실제 연결 변수. 입력 요소 |

원형 아이콘 버튼은 40→20, 52→26처럼 지름의 절반인 반경을 사용한다. 실제 샘플에는 Checkbox/Filter의 반경 6, 외부 래퍼의 반경 0 등 예외가 있으므로 모든 노드를 8 또는 999로 바꾸지 않는다.

### 6.2 간격 [확인 + 확장]

**[확인]** 버튼 간격은 가로 8·세로 12다. 실제 컴포넌트 안에는 4·5·6·8·10·12·14·16·18·20·24 등 다양한 패딩·간격이 있다. 하나의 공식 4px/8px 간격 척도가 명시됐다고 볼 수 없다.

**[확장]**

- 같은 컴포넌트 안의 간격은 기존 값을 우선 유지한다.
- 새 콘텐츠 그룹의 간격은 인접한 기존 화면·컴포넌트에서 역할이 같은 간격을 선택한다.
- 공통 간격 토큰이 필요하면 기존 값의 역할을 정리해 도입한다. 근거 없이 모든 간격을 8의 배수로 반올림하지 않는다.

### 6.4 화면 너비와 배치 [확인 + 확장]

**[확인]**

- 주요 모바일 샘플에는 390 너비의 Status Bar·Region Header, 350 너비의 검색·본문·카드·CTA가 있다.
- 374 너비의 Tab Bar, 342 너비의 Google 버튼 등 다른 규격도 있다.
- Grid 기록 카드는 170 너비다.
- 우측 UI Page를 검토하지 않았으므로 전체 화면 여백·safe area·breakpoint는 아직 확정하지 않았다.

**[확장]**

- 샘플 너비는 기준 크기로 사용하고, 실제 화면에서는 가용 폭 안에 들어가도록 구성한다.
- 390 화면 안에 350 콘텐츠를 가운데 배치하면 좌우 20이 되는 것은 계산상 출발점이지, 모든 화면의 확정 여백 규칙이 아니다.
- 페이지 컨테이너, 안전 영역, GNB/FAB와 콘텐츠의 겹침을 함께 확인한다.
- 좁은 화면에서도 주요 액션과 입력 내용이 잘리지 않도록 한다.
- 데스크톱·태블릿은 모바일 샘플을 단순 확대하지 않는다. 기존 글자 역할과 카드 규격을 유지하면서 열 수·컨테이너 배치를 별도 정의한다.
- EN 번역으로 높이가 달라지는 카드·업로드 영역·헤더는 내용에 맞춰 높이를 늘린다.

기능별 지원 너비와 아래 검증 조건을 작업 기록에 남긴다. 지원 너비가 아직 정해지지 않았다면 해당 기능의 설계 가정을 명시하고, 원본에서 확정된 breakpoint처럼 설명하지 않는다.

| 검증 조건 | 확인할 결과 |
| --- | --- |
| 기준 모바일 예시 | 390 viewport에서 350 콘텐츠 샘플과 시각적 위계·비율 비교. 모든 화면을 350으로 고정하는 규칙은 아님 |

## 9. 데이터와 한·영 전환

**[확장]** 새 기능은 시각적 재사용과 데이터 일관성을 함께 유지한다.

- 같은 컴포넌트의 KR/EN 변형은 같은 의미의 필드·상태·액션을 가진다.
- 문구와 데이터는 분리한다. 카운트가 바뀌어도 텍스트 스타일·정렬·아이콘 크기는 유지한다.
- 긴 지역명, 작성자명, 큰 카운트, 날짜 형식, 2줄 이상 본문, 이미지 없음 조건을 확인한다.
- KR/EN의 문구 속성과 실제 보이는 텍스트를 모두 확인한다. 속성값만 바뀌고 화면 문구가 그대로인 문제를 놓치지 않는다.
- Figma의 `Label#106:0` 같은 자동 생성 접미사를 영구적인 API 계약으로 복제하지 않는다. 역할 이름으로 이해하고 실제 정의를 조회한다.
- 한글 8자·영문 18자는 버튼 라벨 권장 길이다. 모든 텍스트의 최대 길이로 사용하지 않는다.
- 60자 카운터와 ID 4~16자는 해당 샘플 필드의 예시 조건이다. 다른 입력의 비즈니스 규칙에 자동 적용하지 않는다.

### 9.1 언어와 독립적인 데이터 계약 [확장]

아래는 새 기능의 화면 모델을 위한 참조 계약이다. 실제 서버 API가 이 이름으로 구현돼 있다고 주장하지 않는다. 기존 코드에 같은 의미의 키가 있으면 그것을 재사용한다.

| 안정 ID 예시 | KR 표시 | EN 표시 |
| --- | --- | --- |
| `helpful` | 도움돼요 | Helpful |
| `still_true` | 지금도 그래요 | Still true |
| `things_changed` | 상황이 달라졌어요 | Things changed |
| `not_sure` | 잘 모르겠어요 | Not sure |

- 리액션의 선택·카운트·이벤트는 번역 문구가 아닌 안정 ID를 기준으로 연결한다.
- `reaction.id`, `reaction.count`, 표시 문구용 번역 키를 분리한다. 언어를 바꿔도 리액션 ID와 카운트는 바뀌지 않는다.
- `tag`, `watch_count`, `like_count`는 KR/EN이 공유하는 동일한 필드 구조로 다룬다.
- 통계 노출 여부는 두 언어에 공통으로 적용되는 기능 조건으로 제어한다. 언어 코드로 통계를 숨기거나 추가하지 않는다.
- `0`과 값 없음은 구분한다. 값 없음의 숨김·대체 표기 정책을 양쪽 언어에 동일하게 적용한다.

## 10. 새 기능 추가 절차

이 장은 **[확장]** 규칙이다.

### 10.1 6단계 작업 순서

1. **사용자 행동 정의**: 화면의 주 목적과 가장 중요한 액션 1개를 적는다.
2. **기존 요소 매핑 및 범위 확인**: 기능의 각 부분을 8장의 컴포넌트에 연결한다. 전역 내비게이션, 페이지 여백, safe area, breakpoint 또는 화면 흐름을 결정해야 한다면 오른쪽 UI Page나 실제 런타임을 먼저 확인한다. 그 확인 전에는 이 문서로 근거가 확보된 컴포넌트 수준까지만 확정한다.
3. **콘텐츠·상태 정의**: KR/EN, 데이터 길이, 필요한 입력·로딩·빈 결과·실패 상태를 정한다.
4. **최소 확장 설계**: 단순 문구 변경, 기존 속성 추가, 새 변형, 새 컴포넌트 중 필요한 최소 단계를 선택한다.
5. **구현·시각 검토**: 색상·타이포·형태·강조 위계·실제 조작 영역을 기존 기준과 비교한다.
6. **기준 기록**: 새 컴포넌트·변형·토큰의 적용 범위, Figma 노드, 변경 이유와 검증 결과를 기록한다.

### 10.3 새 컴포넌트가 필요한 경우

- 기존 컴포넌트의 의미나 구조를 바꾸지 않고는 표현할 수 없을 때 만든다.
- 이름은 `역할/종류`처럼 의도를 드러내고, 단지 특정 화면 이름만 붙이지 않는다.
- 변형 축은 실제로 독립적인 조건만 둔다. 존재하지 않는 조합을 지원한다고 표기하지 않는다.
- 색상·반경·Typography는 기존 의미 토큰과 역할을 재사용한다.
- 새 토큰이 꼭 필요하면 이름, 의미, 값, 사용 위치, 기존 토큰으로 해결되지 않는 이유를 기록한다.
- KR/EN, 상태, 긴 텍스트, 좁은 화면, 기존 컴포넌트와의 조합을 함께 확인한다.
- 완료 후 8장 목록 또는 별도 확장 목록에 추가한다.

## 18. 개인정보 처리방침 접근성 보완

**[확장 · 사용자 지정, 2026-10-20]**

로그인 A와 B의 개인정보 처리방침 문구에는 다음 규칙을 적용한다.

- 의미 토큰 `color.link` / CSS `--color-link`: `#005FCC`.
- 밑줄을 기본 상태부터 표시한다. 두께 `1px`, 글자와의 간격 `2px`를 사용한다.
- 키보드 `:focus-visible` 상태에는 같은 파란색의 `2px` 실선 외곽선을 표시한다. 외곽선 간격은 `5px`다.
- Paper `#FFFEFB`와의 대비는 약 **5.93:1**이다. 일반 텍스트의 [WCAG 2.2 최소 대비 기준 4.5:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 충족한다. [색상에만 의존하지 않는 구분](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)을 위해 밑줄을 유지한다.
- 타입 B의 Lime `#DEFA5F` 배경과의 대비는 약 **5.11:1**이다.

이 파란색은 원본 Figma에서 추출한 값이 아니라 사용자가 승인한 추가 규칙이다. 현재 원문 연결 전에는 버튼으로 열기 요청을 전달하며, 추후 URL로 이동하는 방식이 확정되면 실제 `href`가 있는 링크 요소에 같은 스타일과 포커스를 적용한다. 이 보완만으로 화면 전체의 WCAG 적합성을 인증하는 것은 아니다.

## 19. 가입 정보와 완료 화면 적용 규칙

**[확인]** [가입 정보 원본 `3499:2868`](https://www.figma.com/design/kq0Gjw4PDPSyHR5aDqaNIs/Hailey.kwon?node-id=3499-2868)은 390 × 844의 Paper 화면이다. 좌우 여백 20px, Pretendard 제목 28/800/1.2, 라벨·캡션 12/400/1.3, 입력·동의 본문 14px를 사용한다. 입력 영역 시작은 y236·y324, 전체 동의 y412, CTA y576이며 CTA는 350 × 52와 pill 반경을 사용한다. 비활성 CTA는 Line 배경·Mute 글자, 활성 CTA는 Ink 배경·White 글자를 사용한다. 상세 좌표와 매핑은 [화면 명세](allearth-app-prototype/SCREEN_SPEC.md)에 기록한다.

**[확장 · 가입 흐름 판단]** 원본의 `아이디`는 인증용 아이디와 혼동되지 않게 `공개 사용자명 (선택)`으로 바꾼다. Google 인증에 별도 로그인 아이디는 요구하지 않으며, 앱 표시용 닉네임만 필수로 받는다. 공개 사용자명을 비우면 서버가 생성한다는 제품 흐름을 채택했으며, 현재 HTML은 빈 값 허용만 구현한다. 실제 자동 생성·고유성 확인·인증은 [별도 구현 대상](allearth-app-prototype/GOOGLE_SIGNUP_FLOW.md)이다.

**[확장 · 폼 상태]**

- 공개 사용자명은 입력할 때만 영문 소문자·숫자·`_` 4~16자로 검증한다. 닉네임은 앞뒤 공백 제거 후 2~12개의 눈에 보이는 글자 단위로 검증한다.
- 오류는 확장 토큰 `color.danger` / `--color-danger: #BF2F2F`와 구체적 문구로 함께 표시한다. `aria-invalid`·`aria-describedby`를 연결하고 오류가 길어지면 필드 높이를 늘린다.
- placeholder는 Mute `#5C5F66`을 사용해 읽을 수 있는 대비를 유지한다. 라벨을 placeholder로 대체하지 않는다.
- 필수 동의는 초기 미선택이며 전체 동의는 부분 선택 상태를 지원한다. 체크박스 주변 라벨도 클릭할 수 있어야 한다. `보기`는 별도 버튼으로 처리해 체크 상태를 바꾸지 않는다.
- 필수 입력과 필수 체크를 충족할 때만 CTA를 활성화한다. 한글 조합·제출 중에는 제출을 잠그고 중복 이동을 막는다.
- 모달은 키보드로 닫을 수 있고 닫으면 실행한 버튼으로 초점을 돌린다. 좁고 짧은 화면에서는 세로 스크롤을 허용하며 필드·오류·CTA를 겹치지 않게 한다.

**[확장 · 화면 전환]** 신규 회원은 가입 정보 → 가입 완료, 기존 회원은 가입 정보를 건너뛴 완료 화면, 취소·실패는 로그인 화면을 유지한다. 완료 화면은 Figma 원본이 없는 프로토타입 확장이며 기존 로고·색상·타이포·CTA를 재사용한다. 현재 전환은 실제 OAuth나 계정 생성 없이 흐름을 검토하는 모의 동작이다.

**[확장]** 검색 결과·나라 이슈·Keep·메뉴 패널은 홈 조작을 확인하기 위한 공용 토큰 기반 UI다. 원본과 동일하게 검증한 추가 화면이라고 주장하지 않는다. 작은 핀은 시각 크기를 유지하면서 터치·키보드 조작 영역을 확보하고, 검색에는 보이는 라벨 또는 접근 가능한 이름을 제공한다. 패널은 닫기·Escape와 초점 복귀를 지원하며 예시 콘텐츠임을 표시한다.

**[확장 · 최초 2D 구현 기록, 아래 §21에서 갱신]** 최초 HTML은 로컬 예시 검색·이슈와 화면이 열린 동안의 Keep 상태를 제공한다. 지구 드래그는 원본 자산을 움직이는 2D 미리보기이며 실제 3D 지리 엔진이 아니다. 기본 보기 버튼은 대한민국 초기 화면으로 복귀하며 기기 위치를 요청하지 않는다. 실제 콘텐츠 API·위치 서비스·계정 저장은 이후 연동한다. 가입 완료의 `내 지구로 가기`가 홈으로 이어진다.

## 21. 전 세계 3D 지구본 확장

**[확장 · 사용자 승인, 2026-10-20]** 원본 Figma 홈의 정적인 바다·육지 SVG를 실제 지리 렌더링으로 대체한다. 회전·전체 국가 탐색·줌을 추가하라는 사용자 요청에 따른 기능 확장이며 Figma 원본 수정이나 원본과의 픽셀 일치를 의미하지 않는다. §20의 SVG 고정 사용 규칙은 이 3D 지형에 한해 아래 규칙으로 대체한다. 기존 SVG는 원본 참고 자산으로 보존한다.

- 바다 `--color-earth-ocean: #B2D0DD`, 육지 `--color-earth-land: #CCE2AA`, 국가 선택 `--color-lime: #DEFA5F`, 배경 Paper, 글자 Ink/Mute를 사용한다. 과도한 우주 배경·위성 텍스처·광원 효과를 추가하지 않는다.
- 상단 검색, 상태 표시, 국가명 Pretendard 28/800, 좌표 Poppins 12, 랜덤 이슈 컨트롤, 하단 pill 메뉴의 기존 시각 체계를 재사용한다.
- 첫 진입과 한국 복귀는 동아시아 방향에서 원본 캡처처럼 크게 표시한다. 2026-11-02 사용자 요청에 따라 390 × 844 기준 바다 지름 약 480px, 양옆 일부 잘림을 적용했다. 짧은 화면에서는 헤더·하단 컨트롤 사이 높이에 맞춘다. `전체 보기`는 별도 거리로 지구 윤곽 전체를 보여준다. 선택 국가명은 `선택한 나라`로 표시해 회전 중 카메라 중심과 혼동하지 않는다.
- 회전은 가로·세로 탐색, 북쪽 방향 유지, 짧은 감속을 적용한다. 자동 회전·자유 pan은 사용하지 않는다. 확대할수록 회전 속도를 낮춘다.
- 핀치·휠·버튼 줌은 같은 범위를 사용한다. `전체 보기`는 방향을 보존하며 축소하고, 한국 복귀는 초기 시점을 복원한다.
- 오른쪽 세로 컨트롤의 버튼은 최소 44 × 44px다. 기존 반투명 White·pill 반경·그림자 규칙을 따른다.
- 새 국가 선택은 라임색 경계/영역 강조와 텍스트로 확인 가능해야 한다. 작은 국가·지역은 검색과 목록으로도 접근한다. 표시 범위는 데이터 출처와 함께 관리한다.
- 국가 시트에는 실제 연결된 콘텐츠가 있을 때만 콘텐츠를 표시한다. 현재는 예시가 지정된 국가 외에는 빈 상태를 보여준다.
- 키보드 회전·확대·복귀, 목록 탐색, 초점 복귀, 동작 줄이기, WebGL 실패 시 국가 목록 이용을 지원한다.

실제 배치와 검증 범위는 [화면 명세](allearth-app-prototype/SCREEN_SPEC.md), [검증 기록](allearth-app-prototype/qa/VALIDATION.md)에 기록한다.
